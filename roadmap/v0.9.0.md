# SIMP v0.9.0 - API Stabilization

**Theme**: Deprecation cycle, interface polish, and backwards compatibility

## Goals

Prepare for 1.0.0 stable release. Finalize the public API, ensure consistency across all functions, and establish long-term backwards compatibility guarantees.

---

## API Review

### Naming Consistency

| Pattern | Standard | Examples |
|---------|----------|----------|
| Constructors | `simp_*()` | `simp_composition()`, `simp_cover()` |
| Families | `simp_*()` | `simp_dirichlet()`, `simp_hurdle_dirichlet()` |
| Model functions | verb first | `fit()`, `predict()`, `validate_composition()` |
| Extraction | noun | `fixef()`, `ranef()`, `coef()` |
| Diagnostics | `check_*()` / `plot_*()` | `check_diagnostics()`, `plot_rhat()` |
| Spatial/temporal | `spatial_*()` / `temporal_*()` | `spatial_car()`, `temporal_rw1()` |

### Argument Consistency

Standardize across functions:

```r
# Consistent: 'newdata' everywhere
predict(fit, newdata = ...)
posterior_predict(fit, newdata = ...)

# Consistent: 'type' for output selection
predict(fit, type = "response")
residuals(fit, type = "aitchison")
pp_check(fit, type = "dens_overlay")

# Consistent: 'component' for component selection
pp_check(fit, component = "sp1")
effect_plot(fit, component = "sp1")
```

### Return Value Consistency

All similar functions return consistent structures:

```r
# All prediction functions return simp_prediction
predict(fit)           # → simp_prediction
posterior_epred(fit)   # → simp_prediction
posterior_predict(fit) # → simp_prediction
```

## Deprecation Process

### Functions to Deprecate

Review v0.1.0-v0.8.0 for:
- Functions with better alternatives
- Experimental functions that didn't work out
- Confusing names

### Deprecation Pattern

```r
# Using lifecycle package
old_function <- function(...) {
  lifecycle::deprecate_warn(
    when = "0.9.0",
    what = "old_function()",
    with = "new_function()"
  )
  new_function(...)
}
```

### Deprecation Timeline

1. **v0.9.x**: Soft deprecation (warning, function works)
2. **v1.1.0**: Hard deprecation (error, suggests replacement)
3. **v2.0.0**: Removal

## Error Messages

### Standardize Format

Use `cli` for consistent errors:

```r
cli::cli_abort(c(
 "Expected a {.cls simp_composition} object",
  "x" = "Got {.cls {class(x)}} instead",
  "i" = "Use {.fn simp_composition} to create valid input"
))
```

### Error Categories

1. **Input validation**: Wrong type, invalid values
2. **Model specification**: Formula errors, incompatible options
3. **Computational**: Convergence failures, numerical issues
4. **System**: Dependencies, file I/O

## Backwards Compatibility

### Guarantees (after 1.0.0)

1. **Exported function signatures**: Arguments won't be removed without deprecation
2. **Return value structure**: Key fields won't be removed
3. **S3 methods**: Standard generics keep working
4. **Fitted objects**: Can load fits from earlier 1.x versions

### May Change

1. Internal functions (not exported)
2. Default argument values (with documentation)
3. Print output format (cosmetic)
4. Warning/error message text

### Semantic Versioning

- **1.0.x**: Bug fixes only
- **1.x.0**: New features, backwards compatible
- **2.0.0**: Breaking changes allowed
